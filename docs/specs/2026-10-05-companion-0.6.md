# Companion 0.6.0 spec

Owner direction (2026-10-05): talk to Companion in plain language; log food and calories, including retroactively and from orders; weekly weight; meal reminders based on usual times and spending; Trip mode; Document vault; replace Needle with a good small conversational model; redesign the UI around these (UI direction chosen separately). Everything runs on the phone.

## Global constraints
- On-device only. Network is used only for model downloads (SHA-256 pinned, public release assets).
- RAM: one big model loaded at a time, through the existing Governor. Conversational model ≤ ~1.6 GB resident, loaded on demand, unloaded after 60 s idle. Never loaded together with ModernBERT or NuExtract.
- Power: chat runs on demand (user is waiting) with 4 threads while charging, 2 on battery, at normal priority while in the foreground. Background parsing (order items, reminders) uses the existing Guard (thermal, battery saver, charging rules).
- Privacy: never log message, chat, food or document text. Vault data is encrypted at rest with a hardware-backed key, excluded from backup, and hidden from screenshots and notifications.
- OTP codes never come from a model. Money amounts from a model must appear verbatim in the source text (existing Verbatim rule).
- Code style: minimal, no comments, short names, pure logic in `core` with unit tests.
- DB: Room + SQLCipher. 0.5.0 ships v8. 0.6.0 migrations start at v9; migration SQL must exactly match entities.

## 1. Conversational engine ("Chat")
- Model: **Qwen3.5-2B** (Apache-2.0) Q4_0 GGUF converted locally from the official `Qwen/Qwen3.5-2B` weights with llama.cpp, unless the model gate below picks **LFM2.5-1.2B-Instruct** (official LiquidAI Q4_0). Published to a `models-v3` release with a SHA-256 pin, like NuExtract.
- Model gate (Mac harness, synthetic prompts only): tool-call validity ≥ 98%, correct tool + arguments ≥ 90% on the food and money suites, Hinglish meal parsing ≥ 85% item recall, first token ≤ 1.2 s and ≥ 8 tok/s on the phone at 4 threads. Pick the best that passes.
- Runtime: reuse the llama.cpp JNI and isolated-process pattern from NuExtract (NuxService). New `ChatService` (isolatedProcess, no network) streaming tokens over Binder. KV prefix cache for the fixed system prompt and tool schema.
- Tool calling: the model emits a JSON tool call constrained by a GBNF grammar generated from the tool registry. The app executes tools in-process (never inside the isolated process) and returns results as a tool message. Max 4 tool steps per turn.
- Tool registry (core interface + app implementations):
  - money: `spend(query)` (category, merchant, period, compare), `bills(range)`, `cards()`, `balance(account)` (stub until balance tracker exists)
  - food: `log_meal(meal, when, items[{name, brand?, qty, unit, size?, mods[]}])`, `food_today(date)`, `set_kcal(item_key, kcal, protein?, carbs?, fat?)`, `log_weight(kg, when)`
  - trips: `start_trip(name, from, to)`, `end_trip()`, `trip_summary(name?)`
  - vault: `vault_find(query)` (returns masked fields; reveal needs biometric in the UI), `vault_add(fields)`
  - general: `remind(text, when)`, `calendar_add(title, start, end?)`, `open(screen)`
- Rules-first: existing Ask rule answers still answer instantly; the model handles everything else.
- Conversation memory: last 12 turns in RAM per session; persisted chat history optional (off by default), encrypted.
- **Remove Needle**: delete NeedleService/NeedleJni/native lib, its model from the manifest and downloads, and its fetch task; route Ask to Chat. Old Needle files are deleted from storage on upgrade.

## 2. Food log
- Data (v9):
  - `meals(id, day INTEGER epochDay, slot TEXT breakfast|lunch|snacks|dinner, at INTEGER, src TEXT chat|order|quick, note TEXT?)`
  - `meal_items(id, meal_id, name TEXT, brand TEXT?, qty REAL, unit TEXT, kcal REAL, protein REAL?, carbs REAL?, fat REAL?, source TEXT sku|brand|db|asked|estimate, conf REAL)`
  - `skus(key TEXT PK = brand|normalized item, brand TEXT?, name TEXT, kcal REAL, protein REAL?, carbs REAL?, fat REAL?, per TEXT serving, updated INTEGER)` — personal foods and brand SKUs the owner confirmed
  - `weights(day INTEGER PK, kg REAL, at INTEGER)`
- Bundled assets:
  - `food_db.json`: generic dishes and ingredients (Indian Nutrient Databank if its licence permits redistribution, otherwise USDA FoodData Central, public domain), per 100 g plus typical serving sizes.
  - `brand_menus.json`: published per-item nutrition for chains the owner orders from (California Burrito, McDonald's, Domino's, KFC, Subway, Burger King, Starbucks, Taco Bell, Chaayos, Third Wave, Box8, Faasos and others), each with `source` and `as_of`. Ships with a schema and loader; data is filled in a later step.
- Resolution order per item: personal SKU → brand menu → food DB (fuzzy, Hinglish aliases like roti/chapati, dal/daal) → ask. Each item carries `source` and `conf`.
- Ask when unsure: if an item has no match or conf < 0.6, the engine returns a clarification ("I couldn't find ghee roast dosa. About how many calories, or should I estimate 350?" / "Small, medium or large bowl?"). The answer is saved as a SKU so it never asks twice.
- Retroactive: `when` accepts relative dates and meal slots ("yesterday dinner", "this morning", "last Sunday lunch"). Pure core date resolver with tests.
- From orders: food orders (Swiggy, Zomato, chains in the brand DB) create a meal at the payment or delivery time. Items come from order emails or notifications when present; otherwise a prompt "₹389 at California Burrito. What did you order?" Customisations adjust kcal by published add-on values or a typical value, marked estimate.
- Health Connect: write NutritionRecord per meal and WeightRecord; read Steps and ActiveCaloriesBurned for a daily balance. Permissions requested only from the Food settings. Skip gracefully when Health Connect is unavailable.
- Targets: daily kcal target from profile (manual or computed from weight, height, age, activity), protein target optional.

## 3. Meal and weight reminders
- Usual meal times learned per slot from logs and food order times (median of last 21 days, defaults 9:00, 13:30, 17:30, 21:00).
- If a slot has no meal by usual time + 60 min and no food payment in the window, notify "What did you have for lunch?" with an inline reply (RemoteInput) parsed by Chat in the background. One nudge per slot per day; quiet hours respected; per-slot toggles.
- Spend-aware: a non-food-chain café or restaurant payment with no items prompts "Logged ₹240 at Third Wave. What did you have?"
- Weekly weight prompt (Sunday 9:00 default) with inline numeric reply; trend line.

## 4. Trip mode
- Data (v9): `trips(id, name, start INTEGER, end INTEGER, budget INTEGER?, currency TEXT?, active INTEGER)`, `trip_items(trip_id, item_id, share REAL default 1)`.
- Auto-suggest from Travel items (flight/train/stay) with dates. Spends between start and end are tagged; forex card messages converted at the rate in the message when present.
- Summary: total, per day, top categories, split tally.

## 5. Document vault
- Data (v9): `docs(id, kind TEXT, title TEXT, fields BLOB encrypted JSON, expires INTEGER?, photo TEXT? path to encrypted file, src TEXT msg|photo|manual, at INTEGER)`.
- Encryption: AES-GCM with an Android Keystore key requiring user authentication for reveal; list view shows kind, title, masked number and expiry only.
- Sources: messages (insurance policy and renewal, vehicle registration, pollution certificate, FASTag, loan accounts, warranties from order emails) via existing extraction plus NuExtract templates; photos via ML Kit text recognition (bundled, offline) then NuExtract.
- Expiry reminders at 30, 7 and 1 days; also mirrored into the Companion calendar when enabled.

## 6. WhatsApp and chats (lands in 0.5.x)
- Business chats resolved through the brand DB are processed like that brand's SMS. Personal chats are kept in a low-priority Chats section instead of being silently folded. WhatsApp Business is listened to. Lost notification access shows a banner.

## Out of scope for 0.6.0
- Price tracking, automatic call answering, Galaxy Watch metrics (later), cloud sync.
